## Feed discovery and link previews

Podcast pages, episode pages and [Podcast Episode Page](/get-started/episode-page) nodes link to their podcast's feed in the page head:

```html
<link rel="alternate" type="application/rss+xml" title="…" href="https://example.com/podcast/1/feed.xml">
```

Browsers, feed readers and some podcast apps find the feed from any of these pages, so listeners can subscribe with the website's address.

Episode pages also have an `og:audio` tag with the episode's audio URL, for link previews in messengers and social networks. With [Analytics](/analytics) enabled, it points to a tracking URL with the source `web`, so downloads from previews are counted separately from the feed.

## Schema.org structured data

The optional **Podcast Publisher Schema.org** module describes podcasts as `PodcastSeries` and episodes as `PodcastEpisode`, Episodes get their name, description, audio, image, episode number, publication date and podcast; podcasts get their name, description, image, author and feed URL. Search engines read this structured data.

1. Install [Schema.org Metatag](https://www.drupal.org/project/schema_metatag), which also installs Metatag:

   ```bash
   composer require drupal/schema_metatag
   drush en podcast_publisher_schema
   ```

2. Open **Configuration → Search and metadata → Metatag** (`/admin/config/search/metatag`). The module adds defaults for **Podcast**, **Podcast Episode**, and **Content: Podcast Episode Page**.
3. Adjust the defaults if you need to. These tokens help:

| Token | Value |
| --- | --- |
| `[podcast:feed-url]` | The podcast's feed URL |
| `[podcast_episode:audio-url]` | The episode's audio URL, tracked if Analytics is enabled |
| `[podcast_episode:duration-iso8601]` | The episode's duration, such as `PT1H2M3S` |

Check a page with Google's [Rich Results Test](https://search.google.com/test/rich-results) or the [Schema Markup Validator](https://validator.schema.org/).
