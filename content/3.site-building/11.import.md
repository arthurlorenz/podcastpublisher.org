---
title: Import a podcast
description: Move a show from another host by importing its RSS feed with episodes, audio files, and metadata.
---

The optional **Podcast Publisher Import** module creates a podcast from the RSS feed of its current host. It downloads the audio files, images, transcripts and chapters to your site, so the show no longer depends on the old host.

```bash
drush en podcast_publisher_import
```

Importing requires the **Import podcasts from feeds** permission. It is restricted: the role creates content and downloads files from other servers to your site.

## Import a feed

1. Open **Podcasts → Import podcast** (`/admin/content/podcast/import`).
2. Enter the **Feed URL** of the show at its current host and click **Continue**. Nothing is imported yet.
3. Check the preview: the number of episodes in the feed, how many are new on this site, the size of the audio files to download, and **What is not imported**.
4. Choose the options and click **Import**.

| Option | Effect |
| --- | --- |
| Publish the podcast and its episodes | Clear it to prepare the move in private. Unpublished podcasts and episodes are not in this site's feed. |
| Only the newest episodes | Imports that number of episodes, counted from the newest, for a trial run. Importing the feed again adds the rest. |
| Add the author as host | Offered when the feed names no people, only an author. Select it if the author is a person. |

The import runs as a batch, one episode at a time, and ends on a result page with the imported, skipped and failed episodes. An episode fails when its audio file cannot be downloaded. A failed image, transcript or chapter file only adds a warning, and the episode is imported without it.

## What is imported

| From the feed | On this site |
| --- | --- |
| Channel | A podcast with title, subtitle, summary, image, email, copyright, explicit flag, type, categories, funding link, license, medium and people |
| Items | Episodes with title, show notes, release date, audio file, image, episode and season number, episode type, explicit flag, keywords, transcripts, chapters and people |
| `podcast:guid` | The podcast's **Podcast GUID**. A feed without one gets the GUID that its feed URL stands for. |
| Item `guid` | The episode's **Episode GUID**, so podcast apps don't show the episodes again as new. |

The import leaves out:

- Episodes without a title or without an audio file.
- Apple Podcasts categories that the site's **Itunes Categories** vocabulary does not have.
- Transcripts in a format the episode's **Transcripts** field does not allow.
- Images, when no image media type is allowed in the [podcast settings](/site-building/fields-and-display).
- Keywords, when the site has no **Tags** vocabulary.
- Episode pages. Create [Podcast Episode Page](/get-started/episode-page) nodes for the episodes that need one.

A feed that is locked with `podcast:locked` is refused. Unlock it at its current host first. Files are only downloaded from public hosts.

## Import again

The podcast is recognized by its GUID. Importing the same feed again adds the episodes that are missing on this site, such as those released since the first import. It does not change the podcast or the episodes that exist already, so your edits stay.

## With Drush

```bash
drush podcast-publisher:import https://example.com/feed.xml --user=1
```

| Option | Effect |
| --- | --- |
| `--user` | ID of the user who owns the podcast, its episodes and files. Defaults to `1`. |
| `--unpublished` | Imports the podcast and its episodes unpublished. |
| `--limit` | Imports only this number of the newest episodes. |
| `--author-as-host` | Makes the feed's author a host, if the feed names no people. |

## Finish the move

An imported podcast has **Replaces an old feed** checked, so its feed tells Apple Podcasts that the show moved here. Then:

1. Check the podcast, its episodes and this site's feed.
2. Publish the podcast and its episodes, if you imported them unpublished.
3. Redirect the old feed to the new one with a 301, and import the feed once more if episodes were released in the meantime.
4. After at least four weeks, uncheck **Replaces an old feed**.

See [Lock or move the feed](/site-building/feed#lock-or-move-the-feed) for the settings involved.
