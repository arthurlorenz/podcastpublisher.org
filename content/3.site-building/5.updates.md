---
title: Update and uninstall
description: Apply new releases safely and know what uninstalling removes.
---

## Update the module

1. Back up the database and the files directory.
2. Update the code with Composer:

   ```bash
   composer update drupal/podcast_publisher --with-dependencies
   ```

3. Run the database updates and rebuild caches:

   ```bash
   drush updatedb
   drush cache:rebuild
   ```

   Without Drush, open `/update.php` as an administrator.

4. Open a feed and check its channel and an episode's enclosure.

Read the [release notes](https://www.drupal.org/project/podcast_publisher/releases) before updating. Releases are still alpha, so a release can change behavior.

Updates do not overwrite configuration on existing sites. If a release changes the default **Podcast Feed** View or the Podcast Episode Page content type, your site keeps its current version. The release notes say when you need to adjust your own configuration.

## Uninstall the analytics module

Uninstalling **Podcast Publisher Analytics** deletes its database tables, including every recorded download.

Before uninstalling it, switch the feed's audio field back from **Download Tracker URL** to **URL to file**, as described in [Analytics](/analytics#_3-track-feed-audio-urls). Otherwise Drupal removes that field from the **Podcast Feed** View during uninstall, and feed items lose their audio enclosure.

## Uninstall Podcast Publisher

Drupal does not uninstall the module while podcasts or episodes exist. The **Uninstall** page (`/admin/modules/uninstall`) links to a page that deletes them. Deleting episodes removes them from the feed and from podcast apps' next refresh.

Uninstalling then also deletes:

- the **Podcast Episode Page** content type and its **Podcast Episode** field
- the **Podcast Feed** View
- the **Podcast 3000x3000** image style
- the **Itunes Categories** vocabulary and its terms

Existing Podcast Episode Page nodes are not converted. Before uninstalling, move content you want to keep to another content type and delete the remaining pages. The **Tags** vocabulary used for episode keywords stays.

Drupal lists the configuration it will delete on the confirmation page. Check that list before you confirm.
